# 工e稳袋 · 预测与留底增强包 v1.0

本包已实现三个增强模块、可独立运行的离线演示、模拟数据、测试和 React/TypeScript 组件。没有收到你们现有项目的源码，因此这是可并入项目的参考实现，**尚未修改或部署你们线上网站**。

全部数据为模拟。成熟统计方法不是本团队原创；不承诺真实准确率、未来安全概率、节省金额或获奖。

## 立即运行

1. 直接双击 `demo/工e稳袋_离线增强演示.html`。没有网络请求、外部字体、CDN、银行接口，不需要安装依赖。
2. 安装 Node.js 24 或以上后，在本目录执行：

```bash
node --test --test-isolation=none tests/*.test.mjs
node scripts/report.mjs
node scripts/build-offline.mjs
```

第一条运行全部测试；第二条重新生成模拟数据与实算误差报告；第三条重新生成离线 HTML。核心和脚本均只用 JS/Node 标准库，不需要 `npm install`。也可用 `node --test tests/*.test.mjs`，某些托管运行环境只汇报文件级计数；关闭测试隔离可展示逐条用例。实测数量与版本见 `docs/test-output.txt`。

需要通过本机 HTTP 打开时，可执行 `node scripts/serve.mjs`，再访问 `http://127.0.0.1:4178`。它只是可选静态文件服务，不是银行接口或权限后端。

## 已经做好的三件事

| 模块 | 实现 | 产品动作 | 强制边界 |
|---|---|---|---|
| 日常现金收付预测 | 上周同一天、同星期中位数、简单指数平滑；滚动选择与独立时间段检验；MAE/RMSE | 第三屏展开“接下来7天日常收付” | 不写入已确认账本，不提高今天的可提用额 |
| 到账延期压力 | 同商户同渠道已完成样本的延期经验统计；正常、手动延期、历史样本压力 | 调整指定结算延期天数，看中途缺口 | 未完成项不记为零延期，不造情景概率，不猜T+1规则 |
| 根据误差建议留底 | 7日窗口最大累计不利误差；经验分位数；取整；本人确认 | 看懂依据后确认是否采用留底建议 | 不自动降低原留底，不自动生效，不称“最优备用金” |

## 目录

```text
core/                  无第三方依赖的计算内核与接入桥
  forecast.mjs         日历日聚合、预测、滚动检验
  settlement.mjs       延期统计、有限情景生成
  reserve.mjs          误差转留底建议、确认应用
  adapter.mjs          CashEvent桥接、计算流水线、过期判断
  adapter.d.mts        React/TypeScript调用契约
  cash-engine.mjs      已有参考时点扫描内核，作为对照保留
  common.mjs           分金额、日期、分位数等纯函数
data/                  3商户×84天、490笔模拟历史交易及未来事件
react/                 可拷入Vite项目的TSX组件、CSS、示例
demo/                  可直接打开的独立HTML与源模板
scripts/               重生成报告、HTML、可选本地服务
tests/                 原内核、增强模块、离线产物测试
docs/                  公式、数据契约、接入、验收、人工答案和答辩
```

React 接入只依赖你们已有的 React 环境；核心是浏览器可直接运行的 ESM JavaScript，并配 `.d.mts` 类型。具体步骤见 `docs/接入与验收.md`。

## 先看这个演示

面馆默认余额3600元、留底600元：按时可提用1200元。把2000元结算款延迟2个自然日到D4，联合约束显示不可行、付款差200元、距留底差800元，显示可提用0元。两情景的**未提用期末余额**均为1800元，但中途支付能力不同。

面馆误差留底建议为800元；本人确认后，按时情景可提用1200→1000元。延期情景仍有付款缺口。建议不会凭空修复现金短缺。

切换水果店：人为设定的经营突变使预选方法在留出段变差，显示需复核；6900元留底建议用于暴露失效风险，不是保证安全的金额。
