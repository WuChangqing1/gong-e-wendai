# 人工标准答案与数据说明

金额表按元展示；代码均为整数分。案例、商户、历史与未来事件均模拟。

## A. 原核心案例

B₀=3600，R=600，x=0时：

| 顺序 | 按时余额 | 延期至D4余额 |
|---|---:|---:|
| t₀ | 3600 | 3600 |
| D1采购1400 | 2200 | 2200 |
| D2到账2000（按时09:00） | 4200 | 尚未到账，仍2200 |
| D2房租1800（18:00） | 2400 | 400 |
| D3退款600 | 1800 | -200 |
| D4到账（延期） | 1800 | 1800 |
| 期末 | 1800 | 1800 |

按时最小余额1800，所以m=1800−600=1200，可提用1200。延期最小余额−200，所以m=−800，x=0也不可行：付款差200、距留底差800，两个缺口不能加成1000。UI显示0不是可行证明。

取x=1200时，按时期末余额600；“两情景期末1800”仅限尚未提用x=0的比较，不可混用。

面馆采用建议R=800后按时m=1000；延期时付款差仍200、距留底差1000，不会因为增加一个参数就消灭资金短缺。

## B. 预测与误差

1. 四个同星期历史100、200、300、1000元：朴素=1000；中位数=(200+300)/2=250。
2. SES，α=.5：100→150→175→187.50→193.75→196.88→198.44（每次更新舍入到分）。
3. 以分为单位，actual=[100,0,-100]、predicted=[0,0,0]：MAE=200/3分；RMSE=√(20000/3)分。MAPE不适用，0分母且净现金流跨零。
4. 第一天不利误差+200元、第二天−200元：累计[200,0]，D=200。只看期末误差0会漏途中缺口。
5. D=[100,200,300,500,900]元、q=.8，nearest-rank序号ceil(5×.8)=4，Q=500。现留底400、取整100元，则建议500。
6. 20笔延迟[0×10,1×6,2×3,3]自然日，q=.9取第18项=2天；第21笔仍未完成，不计入n也不赋0。

## C. 初始时点与单调性

- B₀=600、R=600，未来只有收款无支出：t₀限制x≤0，结果FEASIBLE且0。
- B₀=500、R=600，未来只有收款：起点BELOW_BUFFER，不能说未来有钱所以今天可以提。
- 相同事件情况下只把收入后移，任一时点累计收入不能增加，因此可提用上限不应提高。
- 固定情景提高留底，x上限不得提高。
- 预测收入×10，确定性账本完全不变，则确定性上限不变。

## D. 模拟数据集与真值边界

`data/fixtures.mjs`固定种子：面馆137、便利店811、水果店2026。每户84个完整日，2026-07-10至2026-10-01；分别168、168、154笔历史现金动作，总490笔。水果店包含明确确认的零营业日及人为经营突变。

数据按可复现算法生成，没有筛选“表现好看”的随机种子。三个未来控制案例保持相同，以对照机制；不代表经营历史与当前余额具有真实调查一致性。历史结算配对是描述性测试样本，不是额外应再计入现金账本的一组流水。

`data/simulated-merchants.json`为完整生成物；`data/evaluation.json`为实际计算结果；`docs/模拟运行结果.md`为可直接放进附录的模拟误差表。运行 `node scripts/report.mjs`可重建。

测试中的小例子具有手工真值；真实合成数据的预测误差由程序计算，不是手造“准确率”。当前模拟结果包括变差情形：水果店选中中位数的到账留出MAE约600.85元，高于朴素约456.56元，必须展示需复核。
