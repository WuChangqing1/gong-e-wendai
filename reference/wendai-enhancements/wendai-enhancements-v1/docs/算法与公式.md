# 三个增强模块的公式、推导与适用边界

所有数值例子均为模拟或人工构造。代码内金额为安全整数“分”；MAE/RMSE是诊断统计量，可为小数分，不回写账本。时间使用UTC毫秒，日历聚合固定北京时间UTC+08。没有真实数据准确率或未来概率。

## 0. 保留已有确定性约束层

已确认可用余额B₀，提用额x，事件增减Δ，情景s在关键时点k的未提用余额：

\[
C_{s,k}=B_0+\sum_{j\leq k}\Delta_{s,j},\quad B_{s,k}(x)=C_{s,k}-x.
\]

约束包括初始时点t₀：

\[
\max x;\quad 0\leq x\leq B_0,\quad C_{s,k}-x\geq R_k\ \forall s,k.
\]

令m=minₛ,ₖ(Cₛ,ₖ−Rₖ)。m≥0时x*=min(B₀,m)；m<0时连x=0都不满足，不存在可行提用解，UI显示0并明确不可行。因为t₀在扫描中且R₀≥0，参考代码的m已经不超过B₀。

付款缺口max(0,−C)；留底缺口max(0,R−C)。二者重叠，不能相加。FEASIBLE且x=0和PAYMENT_GAP不是同一状态。所有列出的情景都过约束，是有限情景压力检验，不是完整随机模型或概率保证。

## 1. 日常现金收付预测与对照

### 产品动作与口径

原模型只知道未来已填事件，不能描述日常经营收付节奏。第三屏展开按日期的“预计到账、预计采购”，让商户核对采购安排或结算通知。预测总额与已知未来事件可能重叠，**本版本只单列展示，不加进确定性曲线**。

预测Iₜ=当天实际到账总额、Oₜ=当天实际付出的日常采购总额，两者非负。它们不是下单额、会计收入、利润或家庭消费。净日常流入Nₜ=Iₜ−Oₜ可负。房租、退款、税款独立留在事件账本。

### 方法公式

历史截至第T天，h∈{1,…,7}，对y∈{I,O}分别预测。

**季节朴素基线（上周同一天）**：

\[
\hat y_{T+h|T}=y_{T+h-7}.
\]

需要7个连续完整日。7天以上递推未实现。确认的零营业日保留零，缺数据不能当零。

**近四周同星期中位数**：

\[
\hat y_{T+h|T}=\operatorname{median}\{y_{T+h-7},y_{T+h-14},y_{T+h-21},y_{T+h-28}\}.
\]

需要28天；四数排序取中间两数平均，半分向上取整。它减少孤立尖峰影响，但对持续衰退、换品、节假日结构变化会失效。这是成熟统计思想的应用，不是原创算法。

**简单指数平滑（SES）**：

\[
\ell_1=y_1,\quad \ell_t=\alpha y_t+(1-\alpha)\ell_{t-1},\quad \hat y_{T+h|T}=\ell_T.
\]

演示α=0.3，不自动调优。代码用αBps=3000/10000、BigInt乘加，**每次更新**四舍五入到分。手算比较须用同一舍入规则。SES没有显式趋势和星期季节项，可能明显输给基线。

### 时间顺序验证与方法选择

每户84天。前56天选方法：先用28天训练，起点28…49，每次只用当时前缀预测后7天，共22起点；按验证MAE最低选每个目标的方法，并列保留基线。

冻结所选方法，在起点56…77滚动检验，目标日期只落在第57…84天，22×7=154个误差。最终以84天历史重新估计水平值；不看留出结果偷偷改选再拿同一段宣称提升。

后一个起点可以使用前面已实际发生的留出日，这是滚动运营场景。7日窗口有重叠，154误差不是154独立样本；另输出各预测步长误差，不算显著性、置信区间或真实准确率。

模拟历史没有追溯修订。真实数据须按当时availableAt/version重建历史：仅按日期切分仍可能泄漏后续更正信息。本包没有真实历史版本仓库，不声称解决生产环境全部泄漏问题。

\[
MAE=\frac1n\sum_i|y_i-\hat y_i|,\qquad RMSE=\sqrt{\frac1n\sum_i(y_i-\hat y_i)^2}.
\]

MAPE的分母|y|在y=0时使结果未定义，接近0时异常放大；净现金流跨零或为负时百分比缺乏稳定业务含义。不报告MAPE或“准确率=1−MAPE”。

`diagnostics.needsReview`在预选方法留出MAE高于基线时提示复核；这是描述性门槛，**不是统计漂移检测**，不抹去失败结果。

### 输入输出、函数与人工答案

- `DailyCash[]`：merchantId、day、complete=true、inflowCents、outflowCents、sourceRefs，连续且同一商户。
- `aggregateDaily(transactions,calendar,merchantId,asOf)`：按实际现金到账/付款日聚合。重复cashKey拒绝；转账、拿回家、未到账与非日常款项排除；缺日拒绝，不补零。
- `predict`单一方法；`rollingBacktest`完整各轮；`evaluateForecasts`方法选择、留出误差、未来7日、来源与诊断。
- 预测输出永久为 `provenance:'forecast',confirmed:false`。adapter拒绝直接作为已确认现金事件。
- 手算：同星期100、200、300、1000元，中位数250元，朴素1000元；SES先100元后6天200元，α=.5，每步到分得到198.44元。

### 失效条件与实现范围

默认流水线至少63天，才能完成56天选择+7天留出。样本不足仍能做确定性推演，但没有自动选择/留底建议；低层predict的7/28天最低要求是另一能力。

完整日历日预测批次：例如10月2日00:00生成10月2日至8日预测。晚上仍展示该日的**整日预测**，不是剩余日内到账。展示日期，禁止直接将整日额投入时点余额。缺日、未闭合历史、起点不衔接、经营突变、渠道变化均需复核。

## 2. 到账延期经验描述与有限情景

### 产品动作

原延期天数全凭手填。新增可追溯历史样本摘要，再保留用户压力参数；点击延期天数即可重算中途缺口，不承诺准确预报每笔到账时刻。

同商户同渠道，预计到账aᵢ、实际到账bᵢ：

\[
d_i=\max(0,b_i-a_i),\quad Q_q=d_{(\lceil nq\rceil)},\quad d^*=\left\lceil Q_q/86400000\right\rceil.
\]

d单位毫秒，d*为自然日压力。经验q=.9、最低完成样本12笔均为演示设计参数，不意味90%到账概率，也不证明统计充分。提前到账记0迟到。

仅用knownAt≤asOf、历史预计日期已到且actualAt≤asOf的完成样本。未完成项单独计open/overdue，不冒充零延期。**完成样本仍有删失/选择偏差，不是生存分析**；未完成项多时必须先核对并审查更长压力，不能信赖一个分位数。

\[
\mathcal S=\{\text{按计划},\ \text{指定款延期用户日数},\ \text{指定款延期样本}d^*\}.
\]

仅改指定未完成结算的到账时点a→a+d×一天；金额不变。probability=null；样本不足只给前两个情景，不能解释为无风险。保留手动与历史压力，因此手动调0不会删掉历史压力。

全部情景进入原约束层，取最严格结果。收入迟到超过7日窗口时移出窗口，不强行挤回第7天。

### 输入输出与人工答案

- `settlementStats(pairs,{merchantId,channel,asOf,q,minSamples})`：完成数、未完成数、逾期未完成数、经验延期与sources。
- `buildDelayScenarios(events,{selectedIds,manualDelayDays,stats})`：与原引擎兼容的id/timeOverrides，附basis/sourceRefs/probability:null。
- 模拟20笔完成：0天10笔、1天6笔、2天3笔、3天1笔。q90取排序第18笔=2天。另1笔未完成不进入n=20。
- 2000元从D2挪D4，x=0下期末仍1800元，D3中途为−200元。

### 失效边界

不同渠道、产品、合同、截止时刻不能混合推断。当前校验同商户同渠道；真实上线需增加合同版本/节假日口径。自然日压力不是法定工作日，也不等于T+1/T+N承诺。真正到账时间预测需要合同、完整对账记录、未完成项随访和稳定历史。

## 3. 根据历史误差建议留底

### 产品动作

原R完全手填。用历史预测偏乐观程度说明“为什么建议留这笔钱”，仍由本人决定。它是本包工程启发式，**不是Miller–Orr最优控制限、VaR或概率安全线**。

对滚动起点t、预测步h，到账预测/实际为Î/I，采购预测/实际为Ô/O：

\[
e_{t,h}=(\hat I_{t,h}-I_{t+h})+(O_{t+h}-\hat O_{t,h}).
\]

收入高估或支出低估使e为正。实际现金相对预测累计少∑e，所以每个历史7日窗口中最大的途中偏差为：

\[
D_t=\max\left(0,\max_{1\le h\le7}\sum_{j=1}^{h}e_{t,j}\right).
\]

第一天少200、第二天补200，期末误差0但D=200。只算第7天误差会漏掉途中缺口。

窗口数m，Qq为D样本nearest-rank经验分位数；取整单位g=10000分=100元，现留底Rcurrent：

\[
R_{suggest}=\max\left(R_{current},\ g\left\lceil Q_q(D_1,\dots,D_m)/g\right\rceil\right).
\]

用max而非“R+Q+另一份同类波动缓冲”，避免无理由重复叠加。合同/法律限制的款项要单独核对，不能拿此公式替代不可支配余额或付款义务。

默认q=.9、最低8个完整窗口、g=100元均为设计参数。8不证明统计充分，重叠窗口不独立，q不等于未来90%安全。建议用于复核，不是概率担保。

### 对原约束的影响

建议≥原R且须确认。固定C时提高R只会降低或保持min(C−R)，不能提高可提用额。`applyReserveAdvice`对未来reserveChanges也取max，避免后续时点悄悄降回去。

它仅提示未建模经营波动。当前版本并未把全部未知未来收付写进已确认账本，**不能证明新留底覆盖所有未来支出**。遗漏采购、集中退款、停业、维修都能使其失效。

### 输入输出、人工答案与确认

- `bufferBlocks(incomeFolds,expenseFolds)`：按相同origin/days配对，输出每步累计误差、D和来源，不对齐拒绝。
- `recommendReserve(blocks,{currentReserveCents,q,roundingCents,minBlocks})`：建议、现值、差额、分位数、来源、requiresConfirmation。
- `applyReserveAdvice(engineInput,advice,true)`：返回新输入，不改原对象；未确认或当前留底已变拒绝。缓存必须额外核对basisKey与两类revision。
- D=[100,200,300,500,900]元，q=.8、现留底400元：Q=500，建议500、增加100。
- 模拟面馆实算Q90=775.50元，向上取整800元，按时可提用1200→1000元。
- 模拟水果店Q90=6860元，建议6900元大于当前余额3600。应解释资金/历史波动不匹配、需复核，不能宣传准备6900就安全，更不能自动转借贷。

## 4. 创新定位、复杂度与后续

季节朴素、SES、滚动验证、MAE/RMSE均为成熟方法；Miller–Orr最优控制限依赖不同现金流与成本假设，本包没有实现该原式。不得把本包经验留底包装成经典最优理论。

可主张的工作是：成熟方法与来源账本连接、预测与事实隔离、独立时间段对照、失败结果保留、延期时点约束、本人确认与更正重算。它是特定提用决策中的工程/流程改进，未证明学术原创或竞品领先。

预测参考实现逐起点重算，约O(M·T²+M·T·H)，M=3、T=84、H=7；原约束引擎约O(|S|·NlogN)。不需要预测服务或优化器。

后续生存分析需充分的完成与未完成随访样本及正确风险集；机会约束、CVaR、Wasserstein分布鲁棒需能支撑分布/置信建模的数据与验证；LSTM/MLP需更大样本与防过拟合检验。本次都没有实现，不放进“已具备”页。
