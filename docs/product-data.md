# 产品数据说明

本文说明本环境中**预置产品数据的性质、规模、来源标识与刷新方式**。

> **这是开发与赛事材料口径。**
> 本环境中的预置经营数据是**构造数据**，用于让产品页面呈现完整、相互关联的业务形态。
> 它们**不是**真实工商银行客户数据，**不是**真实银行流水，**不是**任何机构的核验结果。
> 产品界面不对此做任何宣称（不出现「银行已核实」「真实流水」等表述），
> 也不在用户页面显示「模拟 / 仿真 / 演示 / 测试数据」等标签。

## 3. 来源标识（内部）

预置数据在**内部**可识别，但这些标识不出现在普通产品页面上作为标签：

| 位置 | 标识 |
| --- | --- |
| 来源记录 `raw_content` 首行 | `product-data` |
| 历史数据 `source_refs` | `product-data:daily:<date>` |
| 结算记录 `source_ref` / `external_key` | `product-data:settlement:*` / `PRODUCT-DATA-STL-*` |
| 事项编号 `cash_key` | 业务前缀 + 日期 + 序号，如 `SET-20261006-001`；**不含** DEMO / TEST / DEV / SIM |

事项编号按 `reference_at` 动态生成，因此不会因为日期推移而过期。

## 4. 刷新与幂等

```bash
# 只报告将执行的动作，不写入
python scripts/populate_product_data.py --dry-run

# 实际写入
python scripts/populate_product_data.py --apply

# 指定期初时点（缺省为 Asia/Shanghai 当前时间）
python scripts/populate_product_data.py --apply --reference-at 2026-10-04T09:00:00+08:00
```

**幂等策略**

* 资金时点：仅当最新时点的期初不等于目标值时才登记新时点，历史时点保留
* 旧初始化事项：先取消，再把带 `DEMO` 的编号改成中性编号（沿用业务前缀 + 自身日期）
* 家庭邀请码：旧演示邀请码（如 `DEVDEMO1`）换成后端随机生成的邀请码
* 事项：按 `cash_key` 判重，已存在则跳过
* 版本历史：仅当 `current_version < 2` 且该事项在修订计划内时才生成
* 历史数据：按自然日判重，只补缺失的日期
* 结算记录：按 `external_key` 判重
* 协同卡 / 咨询：达到目标数量即跳过

第二次执行应当报告「无待执行动作（数据已就绪，幂等）」。

**安全约束**

* 不创建账号、不修改密码、不创建角色、不触碰 GLM Secret
* 三个正式账号任一缺失即停止并报告，**不会**偷偷新建固定密码用户
* 只做增量：不删除用户、事项、历史、家庭、咨询或来源数据
* 旧演示初始化事项通过 `EventService.cancel_event` 取消（保留版本与来源），**不物理删除**
* 编号规范化只作用于 :data:`LEGACY_CASH_KEYS` 白名单内的三笔记录，
  走 `EventService.update_event` 写入版本历史，绝不改经营者自己录入的事项
* 数据全部经 Service Layer 写入，版本历史、审计日志、来源记录由业务规则自然产生

## 5. 与开发用种子脚本的区别

| 脚本 | 用途 | 是否用于生产 |
| --- | --- | --- |
| `scripts/seed_dev_data.py` | 本地开发种子（固定密码、数据量少） | ❌ |
| `scripts/setup_demo_accounts.py` | 演示账号（固定密码） | ❌ |
| `scripts/populate_product_data.py` | **正式产品数据建设**（幂等、不建账号、不改密码） | ✅ |

开发种子脚本保留开发用途，**不用于生产最终数据建设**：
它们会创建固定密码账号，且数据结构已随产品演进而变化。
