## 2. 录制参数

| 参数 | 值 | 说明 |
| --- | --- | --- |
| 期初资金 | 3600 元 | 由「资金时点」提供，页面不再修改 |
| 经营留底 | **1200 元** | 经营者已在页面上确认过建议留底；在「今日决策 → 建议经营留底」可改 |
| 结算延迟 | **2 天** | 页头「到账延迟 / 共同约束」与「如果结算晚到」共用同一个天数 |

不需要为了录制去改数据库：留底是产品里的正常设置，页面上的数字会随之变化。

## 3. 四个数字（必须完全一致）

| 口径 | 状态 | 可提用 | 最紧时点余额 | 付款缺口 | 留底缺口 |
| --- | --- | --- | --- | --- | --- |
| 按当前计划 | 资金安排可行 | **600 元** | 1800 元 | 0 | 0 |
| 结算延迟 2 天 | 存在付款缺口 | **0 元** | −200 元 | **200 元** | **1400 元** |
| 共同约束（延迟 2 天） | 存在付款缺口 | 0 元 | 同延迟情景 | 200 元 | 1400 元 |

**提醒：付款缺口与留底缺口不能相加。**
留底缺口是「低于留底的部分」，本身已经包含了付款缺口 —— 把 200 与 1400 加起来的
1600 元是错误口径，页面上也专门写了这一点。

## 4. 录制前的自检（30 秒）

1. 打开「今日决策」，确认顶部结论是「资金安排可行 ¥600.00」；
2. 切到「到账延迟」，确认顶部变成「存在付款缺口」、金额 ¥200.00，
   并且下方「资金规划」同步显示「到账延迟：当前存在付款缺口 ¥200.00（状态：存在付款缺口）」；
3. 切到「共同约束」，确认显示「最保守情况：到账延迟」，数字与上一步一致；
4. 「本期资金概览」的每日余额曲线在「按当前计划」与「到账延迟」两种口径下必须不同
   （延迟口径会在结算日出现低于 0 的一段）。

任何一步对不上，先不要录，直接找工程同学。

## 5. 录制时不要出现的内容

* 页面上不应出现「演示 / 模拟 / 原型 / 测试 / 引擎版本 / 内部字段名」这类字样；
* 不要展示 `docs/`、测试报告、终端输出；
* 不要把 1200 元说成「推荐录制参数」—— 它只是经营者的留底设置。
